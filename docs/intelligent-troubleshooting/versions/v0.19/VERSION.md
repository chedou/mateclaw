# v0.19 · 错误码录制证据规模化而不降低晋升门

- 发布日期：2026-08-01
- 架构版本：RFC v4.5
- 图形语义：与 v0.18 相同；本版新增的是回放资格来源与失败隔离决策，不新增第二条诊断流。

## 本版锁定的边界

- 错误码 `MANUAL` Playbook 采用“服务端录制聚合正例 + 封闭判据形状模板”。系统确定性生成排除例和缺证据弃权例，仍执行原有正/负回放门，不能因路由数量多而降门槛。
- 录制种子只允许脱敏、有边界的结构化聚合事实，不保存原始日志、DQL、凭据或真实资产标识。
- 固定回放套件继续 fail-fast；单个生成种子无效时只隔离该 selector，其余固定套件和有效种子仍可加载。
- 历史回放永远不是在线验收。由它产生的 Diagnosis 保持 `fixtureMode=true`，真实 Guance 可信度仍由 T7 owner 验收决定。

## 首个可运行切片

- 新增 `CSDP / csp-rpc-msg / IM1010`：2026-07-31 脱敏聚合事实为搜索命中 2 条、失败样本 2/2 命中特征、成功样本 0/14047 命中特征。
- 候选结论只收敛到“消息发送或 MQ 生产者路径异常待核查”，明确不足以证明 Kafka Broker 故障。
- Demo Seeder 直接消费服务端候选目录，逐条执行 candidate 注册、回放证明、知识审核和版本晋升，不再在 Java 中复制 903001 Playbook。
- 默认八闸门 HTTP smoke 已切到 IM1010，实测得到 `LOCATED / MEDIUM / fixtureMode=true`。

## 仍未完成

- 其余 145 条错误码尚未导入录制聚合种子；D19 解决的是可持续机制，不把首个样本冒充全量覆盖。
- T7 真实 Guance 资产、字段和阈值验收仍需要内网窗口；v0.19 不能替代该验收。

## 与 v0.18 的关系

v0.18 永久保留部署拓扑拨测回归统一 Evidence Spine 的决策。v0.19 复用同一证据脊柱，只补充错误码知识如何获得可规模化、可复算且不降门的回放资格。
