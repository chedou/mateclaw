02

一条证据脊柱，两个闭环

Incident、EvidenceBundle 和 Provenance 共享；故障状态与知识状态独立。故障关闭不等于知识通过，知识审核失败也不回滚故障处置。

Incident Intake企微 / Web / 告警
通道身份、幂等、补问、脱敏
Investigation Plan调查模式、路由权威、证据预算
Loop Control预算、检查点、停止、恢复
Evidence Orchestration只读、有界、canonical
EvidenceBundle日志、PS ID 链路、指标、代码引用
Verify & Decide继续、完成、弃权、转人工

调查内循环 · Runtime Loop

  1. Plan → Collect → Propose → Verify
  2. 预算内按证据缺口继续，不能由模型自行续期
  3. 最终只允许完成、弃权或转人工

知识外循环 · Improvement Loop

  1. PlaybookDraft 接受证据质疑与安全质疑
  2. 确定性回放和人工裁决，不按 Agent 票数
  3. approved 新版本结合 outcome 反馈下一轮

06

三类调查路径，权威单独标记

investigationMode 回答“怎么查”，routeAuthority 回答“为什么选中”。两者不能再压成一个 DETERMINISTIC / LLM_FALLBACK。

ERROR_CODE_PLAYBOOK

错误码确定性路径

明确 `(system,errorCode)` 命中 approved Playbook。选路、取证、判据零 LLM，可到 HIGH。

authority: EXPLICIT / RULE_MATCHED
SCENARIO_PLAYBOOK

场景辅助路径

部署拓扑拨测、慢接口、系统不可用、会话发送失败。模型只能提议已注册 scenarioKey，EvidencePlan 由服务端决定。

MODEL_PROPOSED → confidence ≤ MEDIUM
OPEN_DISCOVERY

未知探索路径

无可用 Playbook 时，受限 Agent 使用唯一只读证据工具。它受 DiscoveryPolicy 约束，不是“已批准知识”。

insufficient evidence → abstain
模型没有画地图的权力。它只能建议使用哪个已审核场景键；DQL、EvidenceRequest、工具名、超时、行数和参数白名单全部来自服务端注册表。

07

Loop Engineering 与多 Agent 结构化反证

Loop 是服务端控制的运行机制；多 Agent 是固定角色的质疑协议。两者都不能改变“证据与人拥有最终权威”。

Investigation Loop Control

  1. 接收 LoopPolicy：迭代、证据、模型、时长、上下文硬预算
  2. 记录 LoopRun：检查点、预算消耗、验证反馈和 stopReason
  3. 只返回 COMPLETE / ABSTAIN / ESCALATE / FAILED

Adversarial Evaluation

  1. Evidence Challenger：反证、矛盾、引用缺口
  2. Safety Challenger：危险动作、越权、虚假高置信
  3. 产出报告；确定性 Gate + 人工审核裁决
Proposal + immutable EvidenceBundle ├─ Evidence Challenger → contradictions[] + missingEvidence[] └─ Safety Challenger → unsafeActions[] + authorityViolations[] ↓ AdversarialEvalReport ↓ deterministic replay gate + human review
状态 · PENDING-EVIDENCE：本节形状目前由预判决定，不由观测到的失败模式决定，因此标记为未生效设计：在 P2 真实样本给出失败模式之前，不得据此新增实现、接口或表结构。P1 仍是一次模型归纳，不实现 Loop Controller 或 Challenger；P2 用 20–30 条历史样本影子评测；P4 才为 SCENARIO / OPEN_DISCOVERY 引入运行时 Loop。ERROR_CODE 路始终固定一轮、零 LLM。
对抗不是群聊投票。Challenger 首期只读冻结 EvidenceBundle，不能直接调用证据源；需要补证时只提交 EvidenceGap。Agent 共识、票数和 Judge 文本永远不能提升置信度或批准知识。

10

安全红线与验收

这些不是“建议”，而是代码、数据库、测试和页面都要能证明的边界。

生产写工具一个都不注册。人工确认/批准只推进状态，系统不执行修改。
错误码命中路零 LLM。模型猜出的 error code 不能回流确定性路由。
原始日志、DQL、凭据不进模型。先限量、脱敏、压缩，只给 LogTraceSkeleton。
模型输出不是证据。所有引用必须属于本次 EvidenceBundle。
candidate 不是 approved。人工审核也必须满足来源资格、回放、幂等和版本唯一性。
fixture 永远可见。Recorded Replay 只证明工程链路，不代表真实 Guance 已验证。
Loop 永远有界。预算由服务端强制，到限必须 abstain / escalate，Agent 不得递归委派或自行续期。
反证不等于裁决。Challenger 不写状态、不直接调用证据源；共识、票数和 Judge 文本不是权威。
首个验收不是文字相似度。人工参考解法拆成必需步骤意图、禁止动作、顺序约束和必需证据类型；完成要求是必需意图全覆盖、引用有效、禁止动作 0，且至少一条负例能 abstain 或审查失败。
