# v0.11 · 第一性原理评价与 RFC v4.1 修订

- 发布日期：2026-07-28
- 图形语义：与 v0.10 完全一致，三张图与 YAML 源原样冻结转入本版本；本次改动只在 RFC 与文档层。
- 新增制品：`architecture-critique-v4.md`（第一性原理评价与修订决议，用户已认可）。
- RFC 升级为 **v4.1**，五处实质修订：
  1. **§5.7 晋升资格分档（D5′）**：原表要求每条 `EVIDENCE_DERIVED` 草稿都先有人工参考解法，
     等于把学习环吞吐封顶在人工产量上，与"知识生产是一等闭环"自相矛盾。
     改为校准期 / 运行期两档，退出校准期的条件是样本数据（≥20 条样本达标且高置信错误为 0），不是日期。
  2. **新增 §5.10 北极星时间戳（D14）**：北极星定义的是人的时间，而预算表量的是机器时间。
     补 `reportedAt / readyAt / conclusionAt / handoffAt`，三段差值分开统计，P1 起就记。
  3. **§6 增加第 2.5 步成功样本对照（D15）**：单样本归纳只是"把人的做法做快"，
     取了成功样本对照才能把"我们有全量日志"兑现成确定性判据；对照缺失只降级不失败。
     §9.1 预算相应由 2 次取证改为 3 次。
  4. **§4.2 / §5.8 / §5.9 标记 `PENDING-EVIDENCE`（A13 / D16）**：Loop Engineering 与多 Agent 反证
     的形状目前由预判决定、不由观测到的失败模式决定；未被真实失败检验过的设计分支
     不得据以新增实现、接口或表结构。D12 / D13 同步标注。
  5. **§9 声明为红线唯一权威清单**：此前同一批约束在 v4 §1.2、v4 §9、HANDOFF、TODO 各写一遍且
     条数措辞不一，"哪一份是权威"事实上已不唯一。HANDOFF / TODO 改为引用。
- 安全边界：无变化。ERROR_CODE 命中路仍零 LLM，生产写工具仍为 0，人工处置与知识批准权未下放给 Agent。
- 实施范围：P1 仍是一次模型归纳 + 确定性校验，新增的只有 T4.5（对照 + 时间戳），
  不引入 Loop Controller、Challenger 或新状态机。
