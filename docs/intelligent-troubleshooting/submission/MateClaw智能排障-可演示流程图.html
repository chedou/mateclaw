开始方式：打开“排障队列”，管理员点击“配置试点”后会直接看到展开的设置、当前阻塞和“两件事可以并行准备”。团队管理员从“补齐试点成员”进入成员页，Guance owner 同时从“登记真实查法”进入三步登记页；两个入口都保留返回当前试点设置的路径。系统会列出最近正式排障单中可直接保存的稳定系统 / 服务供选择；这些旧记录只帮助选范围，不会追溯算成试点成绩。选择只填表、不保存，也不会把展示名称猜成标识。成员准备按职责校验：二线至少是 Workspace 成员，三线复核和数据取证负责人必须是管理员或所有者；因此最小小组是 3 名可操作成员，其中至少 2 名管理员或所有者。成员页会按现状列出最少需要新增或调整的人，并预选正确角色；默认只加入已有账号，只有全局管理员明确选择“新建账号并加入”才会创建账号，账号与成员写入会一起成功或回滚。平台不会代填人员、Owner 查询事实或保存试点计划，登记材料也不会冒充 T7 验收通过。
接力方式：角色就绪后，保存精确系统 / 服务范围和三名不同负责人会开启一个不可变批次；只有保存后新建、非演练且命中范围的 Diagnosis 才冻结到该版本并进入队列。修改设置会开启下一批次，不改写历史。如果负责人离开、停用或失去所需角色，当前计划会按设计停止接力，要求管理员修正。页面按已保存事实引导发起、继续或评估；演练、Recorded Replay 和 fixture 不进入真实效果。
真实性边界：只有真实 Guance、非演练样本进入耗时效果统计。人的复核与采纳成本尚未计量，因此当前不能宣称“已节省多少时间”。

先区分“调查方式”和“只读工具”

SOP、自主规划和多 Agent 不是三种数据源工具，而是组织取证的不同方式。底层日志、调用链、样本对照和拨测工具始终由服务端统一约束。

优先执行已审核 SOP；没有可靠方法或证据时明确停止。规划中能力用虚线表示，不冒充已经上线。

路径 A · 日常主路径已实现 / 首选

标准 SOP

准确命中错误码或业务场景后，冻结已审核版本并按固定顺序取证。

  • 查询、判据和停止条件均已审核
  • 错误码命中路径零 LLM
  • ITGW 904003 已有真实案例
路径 B · 没有可用 SOP按环境受限启用

受限只读调查

只允许使用已登记、白名单内的证据能力，先补事实，不把临时推测当成权威方法。

  • 取得多少证据就展示多少
  • 缺资产、缺路由或缺证据立即停止
  • 输出调查建议或转人工，不输出伪高置信根因
路径 C · OPEN DISCOVERY设计中 / 未投产证明

有界自主规划

未来由模型在硬预算内提出下一步，但只能选择服务端注册的场景与只读能力。

  • 不能生成任意 DQL 或生产写动作
  • 调用次数、时长和停止原因由服务端控制
  • 到达预算或证据不足时必须弃权
后置质量层 · 不是取证主路径规划为影子评测

多 Agent 协同与对抗

会存在，但首期用于复核证据和风险，不在在线命中路径中自由辩论。

  • Evidence Challenger 检查矛盾和缺口
  • Safety Challenger 检查越权和危险建议
  • 不能靠共识、票数或 Judge 文本抬高权威

Tool 接入层：平台可以从哪里取得证据

同一种取证能力可以由不同数据源提供。每个数据源都必须显式配置、只读调用、通过健康检查，并把结果转换成统一证据结构。
