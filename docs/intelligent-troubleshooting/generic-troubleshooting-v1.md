# 通用排障 V1

## 要解决的问题

用户给出一条包含系统、服务、发生时间和异常现象的真实告警后，即使平台还没有该场景的 SOP，也应当能够启动一次受限、只读、可追溯的调查，而不是要求用户先理解或维护“查询合同”。

## 用户主流程

1. 用户在排障工作台或排障机器人中粘贴告警。
2. 系统补齐启动调查所需的最小事实：系统、服务、发生时间和异常现象；错误码不是通用调查的必填项。
3. 内置专用排障机器人默认进入“正式只读调查”；普通工作台仍要求用户明确选择正式模式。两种入口都只使用该系统已接入并验收的数据源执行有预算上限的调查。
4. 系统返回且只返回以下三类结果之一：
   - **已定位原因**：仅限证据已经满足确定性判据的场景调查。
   - **最可能的方向**：通用调查找到可复核证据，但尚不能宣称精确根因。
   - **证据不足**：现有只读数据不能支持判断，并明确说明还缺什么、下一步查什么。
5. 同一会话继续保留诊断上下文；新证据形成新的不可变调查记录，不覆盖旧结论。

## 通用调查边界

- 不要求预先存在 SOP、场景规则或错误码。
- 不以 D20 场景绑定作为通用调查的全局开关；D20 只约束场景级确定性结论。
- 只调用服务端登记并通过验收的只读工具；V1 正式链路仅接受观测云真实证据。
- 调查计划不假设每个系统都有同一套工具：日志、关联链路、K8s 状态中验收了哪些，本次就只查哪些；一个都没有时拒绝假调查。
- 开始调查时冻结本次允许使用的系统、服务、数据端点、只读规则与参数指纹；运行中配置发生变化时失败关闭，不允许“验收 A、执行 B”。
- 有工具调用次数、调查轮次和总时长上限。
- 不调用未启用的模型来补写事实，不把演练夹具当作正式证据，不执行生产写操作。
- 数据源、系统映射和取证规则由管理员集中维护；普通排障用户不需要逐场景配置“查询合同”。

## 怎样扩大可排查范围

通用能力按“系统 / 服务”扩展，不按每个告警场景重新开发：

1. 管理员登记系统与服务的观测资产映射。
2. 管理员为该服务接入并逐项验收可用的只读能力，例如错误日志、关联链路、容器状态。“规则存在”不等于“该能力已验收”。
3. 完成后，该服务下新出现的未知告警即可使用通用只读调查；不需要先建 SOP。
4. 只有当某类问题需要稳定、精确的自动结论时，才追加场景 SOP 和确定性判据。

因此，“取证规则”是管理员复用的平台配置，不是二线或开发每次排障前必填的业务表单。

## 入口行为

### 告警上报接口

`POST /api/v1/troubleshooting/incidents`

- `rehearsal=false` 且没有命中 SOP 时，进入通用正式只读调查。
- 正式调查失败时原样停止，不得静默降级为演练或模型推测。

### 对话入口

`POST /api/v1/troubleshooting/conversation/turns`

- 专用排障机器人默认使用正式只读调查；其他普通聊天员工不自动升级为正式排障。
- 用户可在开始前主动切换为“试用演练”；开始后由服务端锁定本次模式。
- 会话资料完整后，复用与告警上报相同的通用调查链路。
- 同一 IntakeSession 必须幂等：只允许一个正式诊断拥有该会话，并与聊天记录一起持久化。

## 验收条件

- 无 SOP、无错误码的完整告警可以从告警接口和对话入口进入正式通用调查。
- 正式会话诊断写入 `source_intake_session_id`，重试返回同一诊断且不重复调用数据源。
- 同时提交同一会话时，只有一个请求获得调查权，其他请求明确返回“调查进行中”。
- 结果页面和对话摘要不把“候选方向”写成“已确认根因”。
- 正式链路拒绝调用方伪造证据、演练夹具、未验收数据源和生产写工具。
- 只配置一种已验收能力的服务也可启动调查；结果最高是“最可能方向”，不得因为小图全部命中就显示为“已定位根因”。

## 部署开关

通用正式调查不依赖 CSDP 专用 Spring Profile，由部署环境显式开启：

- `MATECLAW_TROUBLESHOOTING_BOUNDED_INVESTIGATION_ENABLED=true`
- `MATECLAW_TROUBLESHOOTING_BOUNDED_INVESTIGATION_PERMITTED_PLATFORMS=guance`
- 可选调整轮次、工具调用次数和总时长上限。

开关只让服务端具备运行能力；每个系统/服务仍必须有精确观测资产和至少一个真实验收过的只读能力。

## V1 不做

- 不扩充具体业务场景 SOP。
- 不开放自由模型规划或多 Agent 投票来决定根因。
- 不支持任何生产变更、自动修复或工单写入。
- 不要求普通用户理解内部的查询模板、字段映射或数据源协议。
