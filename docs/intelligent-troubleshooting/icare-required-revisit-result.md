# iCare 完结前要求填写回访结果

## 结论

**明确排障原因：**本次 `updateFinish` 请求中的结构化回访结果为空，iCare 的完结校验因此拒绝提交。

请求中存在普通回访文字，并不代表结构化“回访结果”已经填写。两者用途不同，不能互相替代。

## 使用方式

在智能排障对话入口粘贴该类告警。系统只在以下三项同时成立时启用本能力：

1. 主机和路径精确匹配 iCare 的 `updateFinish` 接口；
2. `app=CSDP` 是真实查询参数；
3. 错误信息精确表示“需要填写回访信息”，且结构化回访结果为空。

系统随后使用本地 `incident-report@1` 只读工具形成确定性结论，不调用模型、不访问观测云，也不调用 iCare 完结接口。

## 建议处置

1. 在 iCare 工单的回访区域填写结构化“回访结果”；
2. 同时补齐页面提示的其他必填项并保存；
3. 再次执行完结；
4. 若仍失败，使用新的错误信息重新发起排障，避免继续套用本规则。

## 证据边界

- 当前证据能够解释本次请求为什么被拒绝；
- 当前证据不能证明补齐回访结果后一定成功；
- 当前证据不能确认是否还存在其他必填项；
- 平台不会代替操作人填写或提交工单。

## 安全边界

系统仅保留规范化事实：操作名、规则代码、缺失信息类别、建议动作和 `REPORTED` 证据等级。

原始 URL、token、Authorization、人员信息、公司信息、工单号、回访正文和原始请求体均不进入 Diagnosis、审计或详情投影。
