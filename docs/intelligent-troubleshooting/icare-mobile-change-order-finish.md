# iCare 移动端完结被变更单规则拒绝

> 能力类型：已审核的告警事实规范化 + 服务端有界确定性调查
> 自动化边界：只读解释，不调用完结接口，不执行任何生产写操作

## 这类问题是什么

调用 iCare `workOrderPhase/channel/updateFinish` 时，iCare 返回：

> 移动端不支持该操作【工单涉及变更单】；请到 PC 端操作。

这是**业务规则拒绝**，不是网络不通、超时或 iCare 接口不可用。

## 系统如何判断

只有以下事实同时成立才命中：

1. 目标为已复核的 `it-gw.sangfor.com` iCare OpenAPI 路径；
2. 操作为 `updateFinish`；
3. 调用方标识为 `app=CSDP`；
4. iCare 错误文本精确说明“移动端 + 工单涉及变更单”。

任一条缺失时，系统不借用该结论，继续补问或弃权。
系统只信任精确报文解析器签发并随 IntakeSession 持久化的来源标记；直接在
事件 API 中填写相同的系统、服务和标题，不能伪造这份“告警已报告”证据。
错误文本兼容 iCare 已复核的短提示，以及带“PC 端失败后联系技术支持”后缀的完整提示。

## 安全证据

规范化后只保留：

- 操作：`updateFinish`
- 规则：`mobile_change_order_finish_forbidden`
- 客户端：`MOBILE`
- 工单是否关联变更单：`true`
- 建议渠道：`PC`
- 证据成色：`REPORTED`（来自告警中的 iCare 返回）

以下内容不进入 Diagnosis、调查审计或文档：

- URL 查询 token、Authorization；
- 人员 ID、姓名、公司 ID；
- 工单号、客户详细信息；
- 整段请求体与原始错误报文。

## 排障结论与下一步

**直接失败原因：**该工单关联变更单，iCare 的业务规则禁止在移动端完结。

**下一步：**

1. 停止在移动端重试；
2. 由操作人在 PC 端打开同一工单完成完结；
3. 如 PC 端仍失败，使用脱敏工单号和发生时间联系 iCare 技术支持。

**判断边界：**当前证据可以解释“为什么移动端完结失败”；不能证明 PC 端一定能完成，也不判断变更单的状态是否正确。

## 怎样使用

在排障机器人中粘贴包含上述精确路径与错误提示的报文。系统会：

1. 在内存中识别已审核模式；
2. 写入服务端来源标记，并丢弃 token、人员和工单明细；
3. 创建规范化排障事件；
4. 用本地只读确定性问题图得到原因假设，不依赖 Agent 或外部数据源开关；
5. 在对话和详情页返回“原因 + 下一步 + 能力边界”。

同一类完结失败中的其他规则（例如缺少工时）目前不会自动借用本结论；应分别录制样本、复核语义后再增加新的封闭规则。
